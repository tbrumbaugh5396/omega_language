## 1. What this is

A website **designed and built from scratch** for the Client: original design,
custom-built components, and bespoke functionality described in the
requirements document.

No template. Every screen designed, every component built for this project.

## 2. Phases

Work runs in phases, each with its own deliverable, sign-off and payment.
**A phase does not begin until the previous one is signed off.** This is what
keeps a project of this length from drifting.

| Phase | Deliverable | Sign-off |
|---|---|---|
| **1. Discovery** | Requirements document, sitemap, user flows, technical approach | Written approval of requirements |
| **2. Design** | Full design for all key templates, design system, responsive behaviour | Written approval of designs |
| **3. Build** | Working site on a staging URL, CMS configured | Written approval at round 2 |
| **4. Launch** | Live site, handover, training | Acceptance |

## 4. Revisions

**Two rounds per phase.** Design and Build each carry their own two rounds —
this is why the tier costs what it does.

### Phase 2 (Design)
- **Round 1:** homepage and one key template. Direction — layout, hierarchy,
  visual language.
- **Round 2:** remaining templates and refinements from round 1.
- Sign-off ends the phase. **Design changes after sign-off are change
  orders**, because the build is derived from approved designs and reworking
  them means rebuilding.

### Phase 3 (Build)
- **Round 1:** functional review on staging — does it work as specified.
- **Round 2:** polish — content, spacing, mobile, browsers.

### Rules for all rounds
- **One consolidated response** per round, on the supplied form, within
  **[5] working days**.
- Only **[NAMED APPROVER]** gives feedback (Common Clause 4). On projects this
  size, feedback from unnamed stakeholders is the single largest source of
  overrun — the Client is responsible for consolidating internally *before*
  responding.
- No response within **[10] working days** = approval.
- Additional rounds: **$[X]** each.
