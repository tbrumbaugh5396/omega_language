# Every Reward

Predict outcomes, earn credits, redeem rewards. A self-contained full-stack
Python app: FastAPI backend, vanilla-JS PWA frontend, SQLite storage, real
Ethereum integration — packaged like Lingua/Omega with double-clickable
`.command` launchers.

## Quick start

1. Double-click `command_utilities/Install Every Reward.command`
   (creates a private `.venv`, installs FastAPI/uvicorn/eth-account, seeds demo
   data, prints your **admin key**).
2. Double-click `command_utilities/Start Every Reward.command`
   → opens http://127.0.0.1:8850
3. Sign in with a wallet (MetaMask `personal_sign`) or use the dev login with a
   nickname. Enter the admin key to become admin.
4. In your browser: menu → **Install app…** to get the PWA icon/dock app, or run
   `Install App Icon.command` for a Desktop launcher.

`Stop Every Reward.command` stops the server; `Run Tests.command`,
`Back Up Data.command`, `Restore Data.command`, `Uninstall Every Reward.command`
do what they say. `Start Every Reward (HTTPS).command` serves TLS with a
self-signed cert on all interfaces — use it to install the PWA from another
device (expect a one-time browser warning).

## What's inside

- **Three market mechanisms**, selectable per market:
  - **Parimutuel pool** — stakes pool per outcome; winners split the pot
    (minus a configurable rake). If nobody picked the winner, everyone is refunded.
  - **Fixed odds** — house sets decimal odds; payouts locked at bet time; the
    house account carries book risk.
  - **LMSR market maker** — Hanson's log market scoring rule with closed-form
    pricing; prices shown as probabilities; each winning share pays 1 credit.
- **Zero-sum ledger** — every credit movement is a balanced transaction across
  `user:*`, `market:*` (escrow) and `house` accounts. `SUM(delta)` over the
  whole ledger is always 0.
- **Oracles / resolvers** (pluggable per market):
  - `chainlink_price` — reads a Chainlink aggregator over public JSON-RPC
    (e.g. ETH/USD `0x5f4eC3Df9cbd43714FE2740f5E3616155c5b8419`) and resolves
    above/below a threshold. Auto-runs after close via a background loop.
  - `http_json` — fetches any JSON API, walks a dotted path, maps values to outcomes.
  - `manual` — admin resolves from the UI.
- **Crypto, non-custodially** — sign-in is SIWE-style message signing (we only
  recover the address; no keys ever touch the server). Buying credits = send ETH
  from your own wallet to the operator's `deposit_address`, paste the tx hash;
  the server verifies recipient/value/status/confirmations over JSON-RPC and
  credits the ledger. Wallet-authenticated users can only claim transactions
  sent **from their own signed-in address**. The app **never** holds keys or
  sends transactions (the "send with wallet" button just prefills a tx for the
  user to approve in MetaMask).
- **ERC-20 deposits** — besides native ETH, any token configured under `tokens`
  in config (USDC by default) is accepted: the server scans the receipt's
  `Transfer` logs for transfers to the deposit wallet and credits at that
  token's `credits_per_token` rate.
- **Browser extension** — `extension/` is a Manifest V3 wrapper: toolbar popup
  embeds the same frontend (with an offline fallback + configurable server
  URL) and an "Open in tab" button. Load it via `chrome://extensions` →
  Developer mode → **Load unpacked** → select the `extension` folder. Wallet
  sign-in works best in the full tab; dev login works fine inside the popup.
- **Store** — items with prices/stock; redemptions queue for the admin to fulfill.
- **PWA** — manifest + service worker (cached shell, network-first API), icons
  generated by a pure-stdlib PNG writer.

## Configuration (`data/config.json`)

| key | meaning |
|---|---|
| `rpc_urls` | JSON-RPC endpoints, tried in order |
| `deposit_address` | **your** wallet; empty disables deposits |
| `credits_per_eth` | ETH deposit exchange rate |
| `tokens` | ERC-20s accepted for deposit: `{SYM: {address, decimals, credits_per_token}}` — plain tokens only (fee-on-transfer or rebasing tokens would credit the wrong amount) |
| `oracle_max_age_sec` | reject Chainlink rounds older than this (default 6h) |
| `min_confirmations` | confirmations required to credit a deposit |
| `admin_addresses` | wallet addresses that get admin on sign-in |
| `admin_key` | grants admin to dev logins (printed at install) |
| `dev_login` | allow nickname-only login (turn off for real use) |
| `default_rake_bps`, `default_lmsr_b`, `port` | market + server defaults |

## Legal note

This code runs real-money prediction markets if you point it at mainnet and
publish it. In most jurisdictions that is regulated activity (gambling
licensing, CFTC rules, KYC/AML). Shipped defaults are safe-ish (deposits
disabled until you configure them), but **operating this for other people is a
legal decision you own**, not a technical one.
